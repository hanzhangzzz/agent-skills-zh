# 分镜方法：30 秒讲清一个开源项目

## 五幕结构

“画面”列按 editorial 风格描述；其他风格的画面见 `styles/` 配方里的五幕映射，时长与“观众要得到的答案”不变。

| 幕 | 时长 | 观众要得到的答案 | 画面 |
| --- | --- | --- | --- |
| 1 痛点 | 3–5 秒 | “这说的是我遇到的问题” | 浅底。一句痛点大标题 + 一个能看懂代价的示意（token 计数、重复生成、手工重画） |
| 2 亮相 | 2–3 秒 | “它叫什么，承诺什么” | 浅底。项目名大字 + 一句承诺，承诺里只强调一个词 |
| 3 原理 | 9–12 秒 | “它具体怎么做到” | 深色。3–4 步，每步约 3 秒：左侧编号、标题、一句解释；右侧真实界面、真实输出或基于源码的结构 |
| 4 证据 | 5–6 秒 | “凭什么信” | 浅底。一个经过核实的结果：基准数字、真实导出、前后对比；脚注写来源与条件 |
| 5 行动 | 4–5 秒 | “我现在怎么开始” | 浅底。名字 + 收尾句 + 公开安装命令原文 + 仓库地址与许可 |

参考样本：jevgrep 发布视频（30.5 秒）按这五幕排列，证据幕是“SWE-bench 上成本 −40%”并在脚注写明任务数与口径。它的传播力主要来自这个可核实的数字，动画负责把数字讲清。

## 先找“证据幕”

分镜从第 4 幕倒推。按强度排序：

1. **可复现的量化结果**：基准、耗时、成本、体积，附样本与条件。只用项目内或可公开复核的测量。
2. **真实产物**：导出文件、生成结果、运行截图，标注版本。
3. **操作对比**：同一任务“之前要几步 / 之后一步”，两边都是真实操作。

三类都没有时，不编数字；用第 3 类的真实录屏，或先回去产出证据再做视频。

## 第 3 幕先演机制，截图作证据

原理幕是全片最长的一幕，也是最容易变成“截图停 15 秒”的一幕。先回答“产品的机制用一个动词是什么”（路由、组装、过滤、转换……），再用所选风格的原生动作把这个动词演出来；真实截图或录屏在机制讲完后出现，正对镜头停 ≥ 2 秒，作为“它真的这么跑”的证据。

分镜表加一列“主角位置”：写清贯穿元素在这一幕从哪进、到哪去。某一幕写不出主角位置，说明这幕只能靠淡入淡出切换，要重排。

## 按项目形态选择第 3 幕素材

| 形态 | 首选素材 |
| --- | --- |
| CLI | 真实终端输入与输出（录屏或逐字复制的输出） |
| 库 / SDK | 最小代码 → 返回值；函数与字段名取自源码 |
| 应用 / 插件 | 真实界面录屏，裁掉系统信息与隐私内容 |
| Agent skill | 触发语句 → 生成的文件或结果截图 |
| 数据 / 研究 | 数据来源 → 处理 → 可复现的图表 |

## 真实性标签

每个非真实截图的画面都要让观众分得清：

- 示意画面（如痛点里的“坏例子”）：不点名竞品，不模仿特定产品界面。
- 真实录屏：角标写 `REAL RECORDING · <版本> · <界面语言>`。
- 源码驱动的格式展示：字段名和输出格式照源码；示例 id、计数用示意值时写 `FORMAT FROM <file> · IDS SHORTENED` 一类标注。
- 数字：脚注写来源、样本、条件与局限。

## 文案规则

- 每屏只说一件事；标题 ≤ 8 个词，解释 ≤ 1 句。
- 强调色只给一个词：承诺里的动词或关键名词。
- 不写“最强、革命性、10x”等无证据的词；不承诺 Star、增长或未发布能力。
- 视频语言跟随投放渠道：X、GitHub、Hacker News 用英文；B 站、即刻、国内社区用中文。

## 视觉系统（editorial 默认风格）

以下是 editorial 风格（`assets/template.html`）的视觉系统；选了其他风格时，以 `styles/` 中对应配方为准，只保留“单一强调色”和“角标不画进度条”两条通用规则。

- 浅底 `#F2EFE7` 与深色 `#0F1211` 交替：痛点/亮相/证据/行动用浅底，原理用深色，形成“讲故事 → 看机器 → 回到结论”的节奏。
- 衬线大标题（Instrument Serif）+ 无衬线正文（Inter Tight）+ 等宽代码（JetBrains Mono），均为 OFL 字体。
- 强调色从产品本身取（Logo、界面主色、导出结果的主色），整片只用这一种。
- 角标与章节号是画面内容，不要画进度条、时间码、播放按钮。
