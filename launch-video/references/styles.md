# 风格库：先选风格，再写动画

风格是视频的视觉语言，不是证据的替代品。无论选哪种风格，五幕结构、真实素材、可核实数字和安装命令原文都不变；风格决定的是画面怎么组织、东西怎么动、转场怎么发生、听起来像什么。

## 选型流程

### 1. 收集决定风格的信号

从取证结果和用户输入里整理以下信号，缺失的项按默认值填，不逐项追问：

| 信号 | 取值示例 | 默认 |
| --- | --- | --- |
| 投放渠道与画幅 | X/GitHub/HN 16:9；小红书/抖音/视频号 9:16；即刻/朋友圈 1:1 或 16:9 | 16:9 |
| 证据类型 | 量化数字 / 真实产物（图、文件）/ 真实界面录屏 / 终端输出 | 取证结论 |
| 产品机制的隐喻 | 组装、流转、生长、过滤、监控、转换、一步到位…… | 从“原理”幕提炼 |
| 受众与调性 | 工程师、设计师、普通用户；严谨、活泼、文化感 | 工程师、严谨 |
| 品牌资产 | Logo、主色、已有界面风格 | 产品主色 |
| 用户点名的风格或参考 | “做成赛博风”“像这个视频” | 无 |

### 2. 先用硬约束排除

- **素材承载力**：证据是界面录屏或真实导出图时，风格必须能让它在第 3、4 幕以足够大的尺寸清晰呈现。承载力“弱”的风格只能通过“框中框”（卷轴、显示器、纸片、玻璃卡）嵌入素材，嵌入后素材至少占画面宽度的 45%。
- **画幅**：9:16 的风格要单独排版，不能把 16:9 画面裁成竖屏。
- **语言与文化**：水墨、剪纸、综艺花字依赖中文文案和中文语境；英文渠道慎用。
- **可行性**：标为“高”成本的风格，第 5 步试样必须渲染出签名画面，并用静帧证明质感可接受。做不到就换候选，不交付廉价版本。

### 3. 按三个维度给剩余风格排序

1. **隐喻契合**（最重要）：风格的原生动作能否直接讲产品机制。例如粒子聚合可以讲“把零散信息组装成结果”，等轴流水线可以讲“多步骤系统”，一笔线条可以讲“一条命令走完全程”。只有表面好看、讲不出机制的风格排后。
2. **渠道区分度**：同一渠道里同类项目常用的样子（开发工具常用深色终端风）要避开，除非它恰好是最清楚的表达。
3. **制作成本与风险**：时间紧或者素材少时，优先选低成本风格。

### 4. 给出 3 个候选

三个候选彼此差异明显，至少覆盖两个家族（商业动态图形 / 三维 / 视觉潮流 / 艺术复古），分别是：

- **稳妥**：素材承载力强，信息最清楚。
- **契合**：隐喻契合度最高。
- **大胆**：区分度最高，在信息流里最显眼。

每个候选写一行理由，必须引用项目事实（“因为它的核心是 X，这个风格的 Y 动作正好演示 X”）。再写出签名镜头、五幕各一句话、配乐 mood 和成本，最后标出推荐项。用户点名了风格时，只确认可行性，不再另给候选。

### 5. 试样：用真实代码证明质感

每个候选写一个 3–4 秒的试样页，用 `engine.js` 搭，内容包括项目名、承诺句，以及嵌入一张真实素材的原理画面，不画占位框。每个候选渲染 2 张静帧，再拼成一张对比图交给用户选。用户选定之后才写全片。用户要求直接出片或无人值守时，取推荐项，交付时说明理由。

## 所有风格共用的规则

- **单一强调色**依然成立：风格自带的配色是底色，项目强调色只给一个词或一个关键元素。风格规定了固定调色板时（包豪斯红黄蓝、Synthwave 霓虹），强调色从调色板中选最接近产品主色的一种。
- **原生转场**：每种风格用自己的媒介完成转场，例如水墨晕染、纸片翻折、故障切片、粒子炸开，全片保持同一套转场语法，不混用默认淡入淡出。
- **签名镜头**：全片有一个只有这种风格做得出来的镜头，放在亮相或证据幕。
- **真实性标签**照常保留。风格化的“框中框”（显示器、卷轴、贴纸）里放的必须是真实素材，角标照写。
- **阅读时间**：文字入场后的停留时间，中文按 字数 ÷ 4.5 + 1.5 秒，英文按 字母数 ÷ 15 + 1.5 秒；30 秒的片子靠减少每屏字数提速，不靠缩短停留。
- **卡拍**：配乐 `bpm` 确定后，转场与重音放在拍点上（第 n 拍在 `n × 60 / bpm` 秒），cue 时间与画面起动同帧。
