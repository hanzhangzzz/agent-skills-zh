# 视觉潮流

辨识度高，在信息流里很显眼，但容易做出“模板感”。每个风格只取签名动作中的一两个，用在关键处，不要全片铺满特效。

## glass · 弥散玻璃（Aurora / Glassmorphism）

- **签名**：背景是缓慢流动的弥散渐变（几团模糊的大色块），前景是磨砂玻璃卡片：半透明白、背景模糊、1px 亮边，边缘带一点色散。
- **五幕**：
  - 痛点：玻璃卡片上是一串报错或重复对话（示意）。
  - 亮相：色块汇聚，中央玻璃卡片里浮出项目名。
  - 原理：真实截图放在玻璃卡片里（承载力强），卡片依次滑入并叠出层次。
  - 证据：大数字放在玻璃卡上，背景色块随数字变暖。
  - 行动：命令放在玻璃输入框中。
- **转场**：色块整体流动换位，卡片沿 z 轴退后变模糊、新卡片向前变清晰（景深转场）。
- **实现**：背景用 3–5 个绝对定位的大圆，加 `filter: blur(120px)`，位置是 t 的正弦函数。也可以用 WebGL 着色器画域扭曲（domain warp）渐变，更顺滑。玻璃：`backdrop-filter: blur(30px) saturate(1.4)`，`background: rgba(255,255,255,.12)`，`border: 1px solid rgba(255,255,255,.35)`。
- **动效**：背景周期 8–12 秒，不要快；卡片入场 `expoOut`，从 0.96 缩放到 1，同时模糊从 8px 降到 0。
- **色字**：深蓝紫底配青、粉、橙色块，或浅底配粉彩色块；字体用 Inter Tight。
- **声音**：`calm`；卡片入场配 `pop`（轻），亮相配 `reveal`。
- **穿帮**：玻璃下面的背景太平，模糊就看不出来，背景必须有色块经过；文字放在玻璃上时对比度不足，要检查静帧。

## liquid · 液态（金属 / 糖果两种变体）

- **签名**：
  - 金属变体：表面反射彩色环境光的液态铬，流动、拉丝，最后聚成一滴。
  - 糖果变体：饱满光泽的彩色液体，粘连、拉丝、融合、弹跳，像能捏起来。
- **五幕**：
  - 痛点：液滴四散、无法合拢。
  - 亮相：所有液滴融合成一滴，再拉伸成项目名，或者落下溅成字标。
  - 原理：液体流过“管道”或节点，每到一个节点，液滴表面映出（或旁边浮出）真实截图卡片。
  - 证据：液面高度对应数字。
  - 行动：一滴液体落在命令框上，溅开后露出文字。
- **转场**：液体铺满画面，形成下一幕的底色（liquid wipe）。
- **实现**：
  - 2D 糖果变体：metaballs。在 Canvas 或着色器里计算 `Σ r²/d²` 场，按阈值上色，高光用场的梯度近似。
  - 3D 金属变体：全屏 raymarching，`smin` 融合球体；材质取反射方向去采样一张程序生成的彩色环境（几条渐变色带），菲涅耳边缘变亮。
- **动效**：融合和分离都慢进快出，`cubic`；落滴用二次函数加 `squash`。
- **色字**：金属变体用黑底和彩色环境光；糖果变体用粉、紫、橙配深紫底。字体用 Syne 或 Fraunces。
- **声音**：金属变体用 `pulse`，糖果变体用 `bright`；融合配 `drop`，溅开配 `pop` + `thud`。
- **穿帮**：阈值边缘出现锯齿时，用 `smoothstep` 做 1–2px 的过渡；金属没有环境变化就像灰色塑料。

## synthwave · 复古 Synthwave 80s

- **签名**：霓虹网格地面向前滚动，条纹落日（下半部分被横条切开），棕榈树剪影，铬金属渐变大字加霓虹描边，地平线有辉光。
- **五幕**：
  - 痛点：一台复古 CRT 显示器里，真实或示意的报错在闪。
  - 亮相：落日升起，铬金属项目名从远处飞来，霓虹描边亮起。
  - 原理：真实截图放在 CRT 显示器的框里（加扫描线和轻微桶形畸变），显示器停在网格地面上，每一步换一个画面。
  - 证据：霓虹数字配“HIGH SCORE”式的排版。
  - 行动：命令显示在 CRT 终端里，绿色或粉色光标闪烁。
- **转场**：VHS 跟踪错位（几帧横向条纹抖动）加镜头沿网格向前冲。
- **实现**：网格地面用 Canvas 2D 透视投影，横线位置为 `(i + t × 速度) % 1`，再按透视压缩。也可以用 three.js：`GridHelper` 加雾，相机沿 z 移动。落日是渐变圆，用若干横向矩形遮罩切出条纹。铬金属字：`background: linear-gradient(...)` 加 `background-clip: text`，外层叠一层霓虹 `text-shadow`。字体用 Monoton、Righteous；正文用 VT323、Share Tech Mono。
- **动效**：网格匀速滚动，不加缓动；大字飞入 `expoOut`；霓虹灯亮起时闪两下（在 2–3 帧内开关）。
- **色字**：深紫 `#1A0B2E`、品红 `#FF2E97`、青 `#00F0FF`、橙黄落日 `#FFB000`。
- **声音**：`synthwave`；大字配 `reveal`，CRT 开机配 `glitch`，霓虹亮起配 `snap`。
- **穿帮**：网格不按透视压缩会显得平；元素堆太多会像海报模板，棕榈树、落日、网格、铬字四样足够。

## glitch · 故障艺术（Glitch / Datamosh）

- **签名**：RGB 三通道错位，横向切片随机位移，彩条测试图插入 1–3 帧，画面撕裂后恢复。
- **五幕**：
  - 痛点：真实终端或界面正常，然后崩坏（只有痛点幕可以大量使用故障）。
  - 亮相：故障收敛，画面稳定，项目名清晰出现，传达“它修好了”。
  - 原理：干净的真实截图，每一步只在切换瞬间故障 4–6 帧。
  - 证据：数字从乱码稳定成真实值（scramble → settle）。
  - 行动：命令干净地出现。
- **转场**：故障切片转场，6–8 帧，全片统一。
- **实现**：DOM 方案：同一元素叠三层，用 `mix-blend-mode: screen` 和单色滤镜分出 R、G、B，按 t 错开 ±(2–12)px。切片：用多个 `clip-path: inset()` 的副本，各自横向偏移。偏移量用 `rng(Math.floor(t × 24))`，同一帧得到同一结果。Canvas 方案：`drawImage` 按条带重绘。
- **动效**：故障只在节点上爆发，持续 0.1–0.25 秒，其余时间画面干净；乱码数字每帧换字符，最后 0.3 秒按位锁定。
- **色字**：黑底配纯 RGB 和白；字体用 IBM Plex Mono、Space Mono。
- **声音**：`pulse`；每次故障配 `glitch`，数字锁定配 `tick`，恢复配 `reveal`。
- **穿帮**：全片都在故障会让人头晕，也会让真实素材看不清；故障随机数没有绑定到帧，会导致重渲染结果不一致。

## hud · 科幻 HUD

- **签名**：线框地球自转，多层刻度环反向旋转，雷达扫光扫过光点，数据面板里数字流动，四角有括号框，等宽字小号标注（坐标、时间码）。
- **五幕**：
  - 痛点：雷达上大量红点闪烁，告警面板刷屏（示意）。
  - 亮相：刻度环锁定，中心出现项目名，括号框收紧（“LOCKED”）。
  - 原理：每一步是一个 HUD 面板，里面放真实截图或终端输出（承载力强），面板展开时有扫描线划过。
  - 证据：大号数字，旁边配刻度条和小字注释（来源、条件）。
  - 行动：命令放在终端面板里，光标闪烁。
- **转场**：面板沿边框折叠收起，下一个面板展开；或者雷达扫光扫过，扫过的区域切换成下一幕。
- **实现**：SVG 为主。刻度环是 `stroke-dasharray` 圆，`rotate(t × 速度)`；雷达扫光用锥形渐变 `conic-gradient`，旋转角度由 t 决定；地球用 three.js 线框球（`EdgesGeometry` 或经纬线），也可以用 SVG 正交投影的经纬线；数据流数字用 `rng(Math.floor(t × 10) + 行号)`。
- **动效**：环匀速旋转，不同环方向相反；面板展开用 `expoOut`，0.35 秒，先展开横线，再展开竖向。
- **色字**：深青黑底 `#05090B`，青 `#3FE0D0` 为主色，警告用琥珀 `#FFB547` 或红；字体用 Rajdhani、Orbitron、Share Tech Mono。
- **声音**：`pulse`；面板展开配 `blip`，锁定配 `snap`，扫光配轻 `whoosh`。
- **穿帮**：小字太小会糊成噪点，正文不小于 16px；元素过密反而看不清主体，主体必须占画面三分之一以上。

## particles · 粒子成形

- **签名**：数千粒子（5,000–9,000 颗）从星系状旋转聚成文字，炸开，重组成球体，最后变成目标文字或 Logo。
- **五幕**：
  - 痛点：粒子无序漂浮，象征散乱的信息。
  - 亮相：粒子聚成项目名（签名镜头）。
  - 原理：粒子聚成每一步的图标或关键词；真实截图在粒子聚拢后从粒子中“显影”出来（粒子淡出，截图淡入）。
  - 证据：粒子聚成数字。
  - 行动：粒子聚成命令的前缀，再交给 DOM 文字（命令必须清晰可读）。
- **转场**：炸开后重组，全片统一。
- **实现**：目标形状的取样方法：在离屏 Canvas 上 `fillText` 写字或 `drawImage` 画 Logo，再用 `getImageData` 取非透明像素作为目标点（页面走 HTTP，本地图片不会污染画布）。每颗粒子有固定的随机起点和目标点，位置是 `lerp(起点, 目标, ease(p_i))`，其中每颗粒子的进度 `p_i` 有随机延迟，过程中加旋转偏移 `sin`，不做逐帧积分。渲染：Canvas 2D 在 9,000 颗时仍可接受（每帧约 9,000 次 `fillRect`）；更多粒子或需要辉光时，用 three.js `Points` 加 `AdditiveBlending`。
- **动效**：聚合 1.2–1.8 秒，`expoOut`，每颗粒子随机延迟 0–0.4 秒；炸开 0.4 秒，`expoOut`，方向为从中心向外加随机扰动。
- **色字**：黑底配单色或双色粒子，加轻微辉光（`globalCompositeOperation = 'lighter'`）。
- **声音**：`pulse`；聚合配 `reveal`，炸开配 `whoosh` + `thud`。
- **穿帮**：粒子太少，字形就聚不成形；文字取样字号要大（≥ 200px），否则笔画断开；最终的文字和命令必须换成 DOM 才清晰。

## pixel · 像素艺术

- **签名**：低分辨率画布（320×180 或 480×270）用最近邻放大，限定 16–32 色调色板，调色板轮换表现昼夜和光影，元素按像素格移动。
- **五幕**：
  - 痛点：像素小人在迷宫里打转，头顶冒出“?”。
  - 亮相：项目名以像素大字落下（像游戏标题），配“PRESS START”。
  - 原理：每一步是一关，关卡里的宝箱打开后露出真实截图（截图本身不像素化，放在像素边框里，保证可读）。
  - 证据：“HIGH SCORE”面板显示真实数字。
  - 行动：命令放在像素对话框里，逐字打出。
- **转场**：像素溶解（按 Bayer 矩阵阈值逐格切换）或经典的圆形收缩（iris）。
- **实现**：在一个 320×180 的 Canvas 上画，CSS 放大 6 倍并设 `image-rendering: pixelated`。所有坐标先 `Math.round` 再画。调色板轮换：画面存为调色板索引，每帧按 t 换一张颜色表。字体用 Press Start 2P、Silkscreen、Pixelify Sans，中文用 DotGothic16。
- **动效**：角色动画一拍二（12fps 步进：`Math.floor(t × 12)`），镜头移动按整像素；不用缓动的半像素位置。
- **色字**：选一套固定的 16–32 色调色板，全片只用这些颜色。
- **声音**：`chiptune`；跳跃和出现配 `blip`，宝箱打开配 `chime`，关卡切换配 `glitch`（轻）。
- **穿帮**：放大时没有设 `pixelated` 会糊；混用不同像素尺寸会显得廉价；真实截图像素化以后看不清。
