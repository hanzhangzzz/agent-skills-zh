# 方向文件与审片评分：先定方向，再写代码；写完再打分

决定片子好不好看的，是写代码之前的设计（字多大、UI 放大几倍、每秒发生什么），以及写完之后肯不肯看自己的帧。两件事各一节。

## 一、`DIRECTION.md`（工作目录里，写全片前完成）

按下面八项写，每项都要有具体数字或具体引用，写不出就说明还没想清。

### 1. 参考拆解

按 `references.md` 的方法拆一支参考，写 5 条"它用了什么做法、在表达什么"。再写本片采用哪几条、改成什么。

### 2. 产品气质

从仓库和 README 回答，不凭印象：谁在什么情境下用，用起来是什么感觉（冷静、轻快、硬核、安静……）；设计语言（色板、字体、圆角、明暗主题，来源写到文件路径）；母题候选：能直接变成画面的产品元素（logo 几何、核心界面、数据形态、领域隐喻、产品名字面意象）。

### 3. 三个方向，沿不同的轴拉开

| 轴 | 取向举例 |
| --- | --- |
| 底色与光 | 黑舞台 + 发光；纸白 + 墨线；品牌色大色块；明暗交替；真实桌面环境 |
| 字体声音 | 超细大字；粗重冲击；衬线编辑感；等宽技术感；圆润亲和 |
| 母题来源 | logo 几何；界面本身；数据形态；领域隐喻；用户场景 |
| 镜头语言 | 平面排版；3D 舞台；微距特写；一镜到底变形；录屏质感 |
| 转场词汇 | 硬切卡拍；穿越缩放；遮罩擦除；形状变形；匹配剪辑 |
| 节奏 | 发布会式从容；预告片式紧凑；轻快俏皮；安静叙事 |

三个方向至少在三个轴上不同，各自内部自洽，并对应 `styles.md` 里的一个风格 id。写一行理由（引用项目事实），标出推荐项。这一节与 SKILL.md 第 2 步的三候选是同一件事，候选说明直接写在这里。

### 4. 本片专属手法（3–5 个）

每个都写成"因为产品有 X，所以用 Y"。写不出 X 的手法删掉。例子：产品是路由器 → 一张消息卡沿连接器走到工位；产品有快捷键 → 键帽按下作为全片的拍点；产品读本机历史 → 真实会话卡片从磁盘图标里抽出来。

### 5. 禁用清单

点名本片不用的具体模式（参考 `references.md` 共性第 11 条），至少 6 项。泛泛的"不要模板感"不算。

### 6. 画面规范（具体数字）

- 画幅、帧率、底色、安全区（9:16 时关键内容在中间 76%）。
- 字号阶梯：主标题、段标题、说明、角标，中英文分别给字号和字重。主标题 ≥ 画面高度 1/6（1080p 约 ≥ 180 px）。
- 产品 UI 上镜倍数：界面正文在成片里 ≥ 22 px；倍数 ≈ 22 ÷ 原截图正文像素。UI 占画面宽度 45–70%。
- 明暗分段：哪几幕浅底、哪几幕深底、全屏色块砸屏在第几拍。
- 动效语法：入场方式、缓动族、时长范围；本片不用什么。

### 7. 镜头表（到拍）

BPM 定下后 `B(n)`，每个镜头一行：起止拍、主角（只有一个）、画面与动作（带子拍）、上屏文案（≤ 6 词）、声音、素材来源与真实性标签。要求：

- 前 2 秒有钩子；每 3–5 秒一个视觉回报；镜头有长有短（钩子与快切 1–2 拍，机制与证据 4–6 拍）。
- 每个镜头至少一次状态变化或镜头运动；超过 2.5 秒完全不动只能是在给人读字。
- 首帧是完整画面（海报帧），末帧停在 logo + 命令 / URL 的完成态。
- 30 秒片 12–20 个镜头。

### 8. 交付物

成片、海报帧（首帧 / 末帧）、contact sheet、各画幅版本、源 HTML + cues.json、`DIRECTION.md` 本身。

## 二、审片评分（每次全片渲染后）

### 看什么

```bash
ffmpeg -v error -y -i out/silent.mp4 -vf "fps=2,scale=320:-1,tile=6x10" -frames:v 1 out/sheet.jpg          # 节奏与构图
ffmpeg -v error -y -ss <切点-0.4> -t 1 -i out/silent.mp4 -vf "fps=10,scale=320:-1,tile=10x1" -frames:v 1 out/cut-<n>.jpg   # 每个转场
node <skill>/scripts/render.mjs --html promo.html --stills <信息密集镜头的时刻>                                   # 全尺寸看字
python3 <skill>/scripts/motion_check.py --video out/silent.mp4 --scenes <各幕起点>                                # STILL 与 POP
```

用 Read 看每一张。不看图就打分等于没审。

### 打分表（每幕 1–10，全部 ≥ 8 才通过）

| 维度 | 10 分的样子 | 常见扣分 |
| --- | --- | --- |
| 可读 | 隔 3 米能读主标题；UI 正文 ≥ 22 px；对比充分 | 字小、灰字浅底、文字压在复杂背景上 |
| 动感 | 每拍有事、无 ≥ 2 s 的意外静止、换幕靠主角 | 整幕只有一次 rise；截图停 5 秒；淡入淡出 |
| 真实 | 素材是真实截图 / 录屏 / 源码输出，数字有口径 | 画假界面、编数字、候选名不存在 |
| 结构 | 2 秒钩子 → 机制 → 证据 → 收尾，每幕回答一个问题 | 从 logo 开场；功能堆砌；收尾没 CTA |
| 一致 | 一套字体、一套转场、一个强调色、一个主角 | 每幕一种入场；三种转场混用；多个强调色 |
| 卡拍 | 切点与落定在 `B(n)`，音效峰值对齐画面起动 | 手写时间点；音效早于画面 |

### 循环

1. 打分，列出最差的 3 个问题，写明在第几秒、什么现象、准备怎么改。
2. 改 HTML / cues，只重渲受影响的静帧与帧条确认，再全片渲染。
3. 重新打分。直到每幕每维 ≥ 8，且 `motion_check.py` 没有未注明的 STILL / POP，`check_sync.py` 的嫌疑点都看帧确认过。
4. 最少两轮。第一次导出永远是草稿，不是交付。

把每轮的分数与三个问题记在 `DIRECTION.md` 末尾的"审片记录"里，交付时一并给出。
