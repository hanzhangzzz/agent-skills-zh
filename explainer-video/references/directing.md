# 导演方法

这份文件管怎么当导演，`worlds.md` 管画面长什么样，`exemplar.md` 管结构。成片按这个顺序评判：**声音、节奏、镜头、导演**（主角的表演、布景、情绪起伏）。好看的单帧只是起点。

本文方法来自社区实测：Lemo Opuscar（MIT 开源的代码影片风格库）的导演手册，以及“Opus 5.5 做视频：原理、技术栈、实操”的拆解。

## 1. 简报：能问就问一次，不能问就用默认

- **能和用户对话时**，开工前用一条消息问完，之后不再问：
  - 想要什么效果，每个选项写上用什么技术，例如“暗场电影感 → three.js + 后期”“干净排版 → 网页”“手绘 → Canvas 笔刷”；
  - 必须出现的事实、名字或例子；
  - 手上有没有自己的素材（配乐、logo、照片、数据）；
  - 要不要先看分镜（默认不要）。
- **一句话、无人值守时**（`-p` 模式、用户只给了题目）：不问，全部用默认，并在 `PLAN.md` 里写明替用户做了哪些决定。

## 2. Treatment（写进 PLAN.md，在看示例代码之前写）

1. **三个候选结构**，每个写几行：一条旅程、前后对比、倒计时、一份清单最后翻转……写出选了哪个、为什么。对一个题目的第一反应通常是套路，开场画面、结尾和配乐的走向都从题目本身想。
2. **一句话梗概 + 起承转合**：开始是什么样，哪里发生转折，结尾和开头有什么不同。
3. **对标作品**：选 1–2 部给这个题目定标准的作品（纪录片、片头、广告、游戏，或用户给的参考片），写两行：
   - 学什么：构图、节奏、镜头语法、色彩逻辑、配乐结构；
   - 不学什么：角色、具体镜头、旋律、logo、字体。
   对标作品比后面任何规则都更能抬高质量。
4. **一个只有这种媒介能做的动作**，放在情绪最高点。例如墨晕开变成下一幕，一个字变成物体，镜头穿过物体表面进入下一层。
5. **砍掉多余的**：观众在缩略图尺寸能读懂的一个梗，胜过三个看不清的。一个节拍需要解释，就删掉它。

## 3. 证明画风：先出两个方向的关键帧，再做整片

用**真的绘图代码**（不是示意图）渲染两个方向，每个方向一张关键帧，最好就是招牌镜头。两个方向的美术指导要真的不同，比如“暗场微距 3D”和“纸艺长卷”。

```bash
node <skill>/scripts/render.mjs --html index.html --stills <t>      # 每个方向写一个镜头，各出一张
```

- 能对话：把两张图发给用户，等用户选定。
- 无人值守：按第 6 节的评分表给两张打分，选高的，把分数和理由写进 `PLAN.md`。

选定之后才写全片。方向错了，后面一个小时都白做。

## 4. 声音是片子的一半

- **每个看得见的动作都有声音**：落地、翻页、切换、液体、点击、布料。声音要和材质对上，纸、木、金属、墨、玻璃各不相同。
- **三层**：环境声（风、室内、城市、水、机器）、拟音（跟动作走）、音乐。拟音和关键音效出现时，音乐压低。
- **至少两次真正的安静**（或接近安静）：放在转折或情绪高点之前。安静之后的第一个声音，应该是全片最重要的声音之一。
- **用声音做转场**，至少两次：下一场的声音提前进来（J-cut），或上一场的声音拖过切点（L-cut）。
- 写一张**声音设计表**：每一段的环境声、主要拟音、音乐状态（铺底、推起、安静、落下）。

## 5. 节奏与镜头

- **先定节拍网格再做动画**：`EX.tempo(bpm)`，切点、关键动作、字幕落在拍子上。不必每拍都切，留出看的时间。
- **快慢交替**：至少一次明显的加速或减速，给观众一次喘息（一个长镜头或一次停顿）。全片一个速度就是失败。
- **至少四种不同的镜头运动**，景别真的在变（远、全、中、近、特写）。2D 也有镜头：推、拉、视差、焦点转移、画中画。
- **一个让人记住的招牌镜头**：一镜到底、尺度揭示，或用媒介本身完成的转场。
- **转场长在媒介里**：翻页、刻线生长、墨晕开、穿过表面，全片用同一套转场语法。避免默认叠化和生硬切换。
- 关键时刻，主体至少占画面高度的三分之一，剪影清楚。

## 6. 导演评审：拼图打分，每项 ≥ 8 分才继续

每写完一批镜头，以及交付前，都做一次：

```bash
node <skill>/scripts/render.mjs --html index.html --sheet auto       # 9 个关键时刻拼成一张 out/keyframes.jpg
```

用 Read 打开拼图，当一个挑剔的导演，按下面 6 项打 1–10 分，写进 `REVIEW.md`（轮次、分数、问题、改法）：

| 项 | 8 分是什么样 |
|---|---|
| 开头抓人 | 前 2 秒就有一个让人想看下去的画面或问题 |
| 一眼看懂 | 每格的主体清楚、够大、够亮，离开字幕也知道在讲什么 |
| 美术统一 | 每格都守住美术指导：只用调色板，没有平涂卡通、白卡或杂色，光晕不发白 |
| 镜头与转场 | 景别和运动有变化，转场是设计过的，没有空白帧 |
| 节奏 | 快慢有起伏，字幕读得完，没有一帧塞太多东西 |
| 讲清楚 | 每章一个概念，有具体数字或名词，事实准确 |

有一项低于 8 分，就改代码重来，最多三轮。三轮后仍不到 8 分的项，交付时如实说明。打分要严：给 9 分要说得出它比 8 分好在哪。

**别把示例再做一遍**：评审时和你读过的示例比 6 个方面（结构、开场、招牌镜头、镜头路径、配乐走向、结尾），至少 4 个要不同。

## 7. 先出 15 秒样片

全片渲染之前，先把开头约 15 秒连同声音完整做出来：

```bash
node <skill>/scripts/render.mjs --html index.html --range 0:15 --subframes 2    # → out/sample.mp4
```

再配上声音，按第 6 节检查一遍：开头抓不抓人，节奏、声音和运动模糊对不对。能对话就发给用户确认；无人值守就自己抽帧检查（`ffmpeg -vf fps=5,tile=…` 看关键动作的逐帧条），没问题再渲全片。

## 8. 最常见的失败

- 主体太小、太远，或贴在画面边上。
- 太暗看不清，或者同色叠同色（红底上的红字）。
- 字幕挡住主体。
- 一个梗或一次失败太快，观众没看懂。
- 转场里出现空白帧。
- 光晕太亮，画面发白。
- 一帧里画了太多东西。
- 渲染慢得离谱：在页面里逐帧画颗粒，或者 CSS `filter: blur` 用在会动的东西上。
- 跟随主体的效果（放大、聚光、跟拍）在相机移动后没跟上主体：屏幕坐标一律从同一个世界坐标换算出来。
