# 美术指导、视觉世界与镜头

范例式的讲解片是“会动的信息图”：固定机位，一页一页叠化。社区里最好的片子做了三件不同的事：

1. **美术指导先行**：一支片子只说一种视觉语言。例如《代码即动画》全片只有黑底、暖白字和一种橙色；《一座城的年轮》是灰白模型加每个时代一种发光色。
2. **造一个世界，用镜头拍它**：主角在世界里走，镜头跟着推、拉、摇、穿越尺度，变速推进，再稳稳停住。
3. **质感**：用真实光照的材质，配辉光、景深、暗角、颗粒和运动模糊；文字本身就是画面，不装在 UI 卡片里。

本文件帮你在写分镜前定下这三件事。

可运行的示例：
- `assets/cinema.example.js`：暗场电影感 3D，加后期、动态排版和变速运镜，讲一块芯片里有什么，效果见 `assets/cinema.jpg`。**质感的标准看它。**
- `assets/world.example.js`：2D 世界、相机和深色主题，讲阳光到你眼里的 8 分 20 秒。
- `assets/three.example.js`：three.js 3D，标签贴在 3D 点上，讲为什么会有四季。效果见 `assets/worlds.jpg`。

## 0. 什么会让片子看起来像“复古 Flash 拼接”

下面五样同时出现，观众就会觉得廉价。避开它们，比加任何特效都重要。

- **SVG 平涂渐变插画**：卡通比例，没有光影。
- **调色板太散**：五六种高饱和色一起用，没有主次。
- **白色圆角卡片当信息载体**：画面像 App 界面贴在插画上。
- **镜头和元素匀速运动**：所有动作同一种节奏，不卡拍子。
- **零后期**：边缘锐利、没有景深、没有颗粒，看起来像矢量预览图。

## 美术指导卡（写进 PLAN.md，所有镜头服从它）

```
风格：一句话 + 参照（例：暗场电影感 3D，像《代码即动画》；灰白模型数据城，像《一座城的年轮》）
调色板：底色 / 主色 / 唯一强调色（其余只用灰阶；强调色只给主角和此刻最重要的一个词）
字体：大字（Noto Sans SC 900，字号 160–400 px 的巨型字）/ 正文 / 数字与微标签（JetBrains Mono 18–24 px）
材质与纹理：例：拉丝金属 + 硅片反光；纸纹；粘土哑光；线框发光
后期：辉光（只给强调色）/ 景深 / 暗角 / 颗粒 / 运动模糊（EX.run 的 post 和渲染的 --subframes）
运动性格：例：变速推进再稳停（EX.ramp），落点卡拍子（EX.tempo）；或者慢推长镜头
转场母题：例：上一幕的元素变成下一幕的开头（形态变换）；穿过物体表面进入下一层
外观：chrome（cinema 无框，或 pill 玻璃胶囊）、theme（dark / 自定义）
```

规则：
- 画面里只出现调色板里的颜色。
- 粉彩卡片组件（`.card .tag .node .tok`）只在“粉彩信息图”世界使用。其他世界的数据标注 = 大号数字 + 一根细线 + 等宽小标签。
- 全片至少 2 个镜头以动态排版为主视觉：巨型字或数字就是画面，用 `EX.sweep` 让颜色逐字扫过，用 `riseChars` 逐字升起，也可以让字贴在 3D 曲面或路径上。

## 1. 怎么选世界

1. **看题材的物理真相**：讲的东西本来长什么样、在哪里发生？
   - 有实体：飞机、心脏、发动机、地球，先考虑 3D 或剖面。
   - 发生在一段路上：咖啡从农场到杯子、一封快递、一度电，先考虑长卷旅程。
   - 跨尺度：细胞、原子、芯片、宇宙，先考虑尺度穿越。
   - 只存在于系统内部：网络请求、算法、支付，先考虑信息图或深色科技。
   - 关于人和年代：历史、文化、演化，先考虑纸艺 / 手绘。
   - 关于数量：人口、气候、经济，先考虑数据可视化。
2. **列 3 个候选**写进 `PLAN.md`：稳妥（粉彩信息图）、契合（最贴题材的那个）、大胆（观众没想到但说得通的）。选**契合**或**大胆**；粉彩信息图只是保底，题目没有实体、没有路线、没有尺度时才选它。3D 加后期渲染约每秒 15 个子帧（macOS 用 GPU；140 s 的片子开 2 倍运动模糊约 10 分钟），这是可接受的成本，不是放弃 3D 的理由。
3. **定招牌镜头**：写下 2–3 个只有这个题目才有的镜头，例如“镜头从一颗咖啡樱桃推进到果核里的两颗生豆”“飞机掠过时，机翼上方的流线被拉弯”。它们是观众会记住和转发的画面，分镜围绕它们排。
4. **定运镜**：分镜表每行写一个镜头运动（见第 3 节）。整片至少一半镜头的相机在动，至少一次尺度穿越或长距离跟拍。

## 2. 世界目录

每种世界写了：适合什么题材、它的招牌镜头、框架里怎么搭、关键技法、最容易出的错。

### 暗场电影感 3D（质感上限，强模型首选）
- **适合**：芯片、发动机、宇宙、人体、AI、能源，任何能做成一个“物件”或“场所”的题目。
- **招牌**：变速推进穿过物体表面进入下一层；巨型数字压满画面，强调色逐字点亮；镜头低机位慢推，背景景深虚化。
- **搭法**：`EX.backdrop({ subject: true })` 放 three.js，用 EffectComposer 串起 RenderPass → UnrealBloomPass → BokehPass → OutputPass；`EX.run({ theme: 'dark', chrome: 'cinema', post: { vignette: .45, grain: 6 }, mood: 'pulse' })`，加 `EX.tempo(96)`。照 `cinema.example.js` 写。
- **技法**：
  - 辉光只给强调色：其他材质的亮度压在辉光阈值以下。
  - 质感：金属或硅片用 `MeshPhysicalMaterial`，反射用 `RoomEnvironment`。
  - 标注：DOM 文字用 `pin()` 贴在 3D 点上。
  - 交付渲染：加 `--subframes 2–3`，开运动模糊。
- **坑**：
  - 全场都在发光，看起来就成了霓虹灯牌。
  - 景深焦点没跟主角，主角是糊的。
  - 背景纯黑没有一点环境光，物体像剪纸。
  - 用了白卡和胶囊，电影感当场破功。
  - 环境反射用了 `RoomEnvironment`：那是一个白房间，深色表面斜看会反出一片灰。暗场改用黑底加几块柔光板的环境，金属度 ≤ 0.5，否则物体整块发黑。
  - 辉光阈值按亮度算：橙色 `#FF6A1A` 的亮度只有约 0.32，发光材质的颜色要乘到 ×5 以上才会亮。同时亮的东西要稀疏（约 2–3%），否则像霓虹灯牌。
  - 跨几个数量级推进时，相机近远裁剪面、雾、阴影范围、灯光位置、景深光圈都要随相机距离缩放（光圈取 常数 / 距离），推进的目标点放在原点。
  - `text-transform: uppercase` 会把 µm 变成 ΜM；等宽字体里写中文要补 Noto Sans SC 回退；逐字发光的 `text-shadow` 写在 `.ch` 上，才会跟着 `EX.sweep` 变色。

### 动态排版（文字即画面）
- **适合**：观点、数字、定义、对比，以及没有实体的概念（AI 安全、通胀、注意力）。
- **招牌**：一个巨大的数字或词占满画面，颜色逐字扫过；字沿着曲线排开；上一个词的某个字母变成下一个画面的形状。
- **搭法**：镜头 html 里放 160–400 px 的字；init 里 `splitChars(el)`；render 里 `EX.sweep(el, u, a, b, 强调色)` 或 `riseChars(el, u, a)`；配 `chrome: 'cinema'`。
- **坑**：
  - 字太多：一屏最多一个大词，加一行小字。
  - 只有淡入：字必须有位移、缩放或逐字变化。
  - 字体只用一种字重：要用 900 大字配细的等宽小字，拉开对比。

### 粉彩信息图（模板默认，保底）
- **适合**：软件、网络、算法、支付这类没有实体的系统流程。
- **招牌**：主角形态链（明文 → 乱码 → 光脉冲 → token），continuity cut。
- **搭法**：默认页面即可。镜头之间仍可用 `at` + `fly` 平移，比叠化更有空间感。
- **坑**：全片都是居中卡片 + 叠化，就成了幻灯片。至少用相机把相邻站点连成一条路。

### 长卷旅程（2D 世界 + 相机跟拍）
- **适合**：一个东西从哪来、一条链路上的每一站（农场 → 工厂 → 港口 → 门店）。
- **招牌**：一镜到底跟拍主角沿路走，站点是路边一个个场景；仪表是距离或天数。
- **搭法**：`EX.world` 画整条路和沿途地景（坐标可以到几万像素），每个镜头用 `at` 摆在路上的站点；跟拍用 `cam(u, d)` 返回主角当前位置。远景层（山、云）放 `EX.backdrop`，按 `EX.cam(t)` 做慢速视差。
- **技法**：路径用 SVG path，主角位置用 `path.getPointAtLength`，相机取同一点并加 0.2–0.4 s 的滞后（取 `u - .3` 时刻的位置），显得有呼吸；地景元素按 `rng` 散布，只在 `init` 生成一次。
- **坑**：
  - 站点间距太近，镜头一直在小幅抖动。站点相距至少 1.5 屏，飞行 1.2–2 s。
  - 平涂卡通插画加白卡，就是 Flash 感。地景要有光影和纹理：天光渐变、物体阴影、远景层降饱和并模糊（`filter` 只给静态层）、近景虚化；整条路服从一套调色板。

### 尺度穿越（Powers of Ten）
- **适合**：微观和宏观，比如细胞里的蛋白质、芯片里的晶体管、太阳系到银河。
- **招牌**：镜头从日常物件一路推进到 10⁻⁹ 米，或从地面拉到宇宙；仪表是尺度 10ⁿ m（非时间仪表，不显示倍数）。
- **搭法**：下一层镜头用 `at: [x, y, s]` 嵌在上一层镜头的某个细节里，s 取 0.05–0.15。`fly` 会让细节所在的点保持不动，读起来就是“推进去”。上一层要先把那个细节画出来（一个小框、一个高亮点），观众才知道要进哪里。
- **技法**：每层留一个“门”：高亮圈 + 标签“放大 ×20”；推进前 0.5 s 先让门亮起来。层与层之间的配色要连续：上一层的门是什么颜色，下一层的底就是什么颜色。
- **坑**：一次推进超过 ×30，中间帧会糊成色块，拆成两次飞行；门没画就推进，像是随机跳转。

### 3D 实物（three.js）
- **适合**：有形状的东西：飞机、发动机、心脏、地球四季、建筑结构、分子。
- **招牌**：镜头环绕主体；爆炸图把部件拆开；剖切面露出内部；标注线从 3D 表面引出。
- **搭法**：工作目录 `npm i three`，`shots.js` 第一行 `import * as THREE from 'three'`。WebGL 画布放 `EX.backdrop`，每帧在 `render(el, t)` 里按当前镜头设相机。文字、数字、标签放镜头的 DOM 里，用 `vector.project(camera)` 把 3D 点换成屏幕坐标贴上去，详见 `three.example.js`。
- **技法**：
  - 光：主光带软阴影 + 轮廓光 + 半球光。
  - 质感：哑光粘土色（roughness 0.7–0.9），或者金属漆（`MeshPhysicalMaterial`，clearcoat）。
  - 渲染：`setPixelRatio(2)` 超采样，`preserveDrawingBuffer: true`。
  - 位置：所有姿态都是 t 的闭式函数。
- **坑**：
  - 没有轮廓光，物体会融进背景。
  - 用 `OrbitControls`、`clock`、物理引擎逐帧推进会错帧。
  - 3D 文字糊，文字一律用 DOM。
  - 渲染比 2D 慢，调构图用 `--stills`，不要反复渲整片。

### 等轴 2.5D 小世界
- **适合**：很多角色同时运作的系统：城市供水、工厂流水线、快递分拣中心、生态系统。
- **招牌**：俯视的积木世界一块块搭起来，小车、小人、水流同时在走；镜头在世界上空平移，推近某个格子。
- **搭法**：`EX.world` 画等轴网格和建筑；每个镜头 `at` 对准一个区域；`fly` 在区域之间平移。
- **技法**：等轴投影 `sx = (gx - gy) * 64`、`sy = (gx + gy) * 32 - gz * 64`；方块三个面用同一色的三个明度（顶面最亮）；按 `gx + gy` 从后往前排 z-index；沿格子路径走的小车，位置是 t 的分段线性函数。
- **坑**：遮挡顺序错了，方块会互相穿插；元素太多太小，像地图截图，主角必须比路人大一号并有描边。

### 深色科技 / 星空
- **适合**：太空、电与磁、计算机内部、夜间发生的事、光。
- **招牌**：发光的主角在暗场里穿行，留下拖尾；星点有视差；数据像电流沿线路流动。
- **搭法**：`EX.run({ theme: 'dark' })`；星空或粒子用 `EX.backdrop` 里的 canvas，按 `EX.cam(t)` 做视差。
- **技法**：发光用 `radial-gradient` 叠层或 canvas `globalCompositeOperation = 'lighter'`，不用 CSS `filter: blur`（每帧重算，很慢）；拖尾 = 主角过去 0.5 s 的位置串，透明度递减，逐点按 `u - k * .03` 算出来。
- **坑**：星点每帧重新随机会闪烁，必须 `rng` 一次生成；全片只有暗蓝一种颜色会闷，给每章一个亮色。

### 数据可视化
- **适合**：人口、气候、经济、能源这类“有多少、怎么变”的题目。
- **招牌**：数据本身变形：一万个点从人口地图聚成柱状图，再散成时间线；一根曲线画到今天，镜头顺着它推到峰值。
- **搭法**：真实数据写在 `PLAN.md` 的事实表里，并写进 `shots.js` 的常量（年份、数值、来源注释）；一个镜头的图形在下一个镜头变形，接 `enter: 'cut'`。
- **技法**：点阵变形 = 每个点有 A、B 两个目标位置，`lerp(A, B, cubic(prog(u - i * .0005, …)))` 错开出发；坐标轴先出（骨架先立），数据后长；关键数据点用大号数字 + 引线标注。
- **坑**：编造数据。没有可靠来源就换题或标“示意”；点数超过 5000 改用 canvas 画，DOM 会拖慢渲染。

### 纸艺 / 手绘 / 水墨
- **适合**：历史、古代技术、文化、生物演化、童话感题目。
- **招牌**：纸层视差的手卷横移；毛笔一笔画出山和河；手绘角色演示一个动作。
- **搭法**：在 `explainer.html` 的“add your own”区覆盖 `#stage` 背景为纸色（`#F2ECDE` / `#F5EBD7`），把 `#bg .blob` 和 `.grid` 设为 `display:none`，HUD 变量改成墨色；纸层放 `EX.world`，每层按深度乘以相机位移做视差。
- **技法**：
  - 纸纹：预生成噪声 canvas，`mix-blend-mode: multiply` 叠一层。
  - 剪纸投影：`drop-shadow` 只给静态层。
  - 手绘抖动：每 2 帧换一个 `rng(Math.floor(t * 12) % 3)` 种子。
  - 水墨：多层淡墨山脊，越远越淡。
- **坑**：留白不够就不像水墨；手绘线太细（< 3 px）压缩后会消失；抖动每帧都换会太闹。

### 剖面图鉴
- **适合**：一个东西的里面是什么：地球内部、发动机、种子、电池、耳朵。
- **招牌**：外壳像被刀切开一样打开，露出分层；每层引出一条标注线；镜头推近某一层，进入下一章。
- **搭法**：剖面主图放一个镜头，后续“推近某一层”的镜头用 `at` 嵌在那一层上（同尺度穿越）。画法参考 `gallery.example.js` 第 1 段（剖面 + 引线）。
- **坑**：分层只画描边会被 `THIN` 拦，要用渐变填充；标注挤在一侧，`OFF-CENTER`。

## 3. 运镜词汇（分镜表“镜头运动”一栏从这里选）

变速是高级感的来源：在场景之间加速推进（`flyEase: EX.ramp`，先慢、中段冲过去、再长长地减速停稳），停下后留出 ≥ 3 s 稳定展示。镜头时长和落点取整拍（`const B = EX.tempo(96)`，`dur: B(12)`，音效放在 `B(n)`），配乐按同一速度合成，画面就会卡拍子。


| 运动 | 什么时候用 | 写法 |
|---|---|---|
| 固定 + 微推 | 要读的镜头（数字、标注多） | 只写 `at`，框架自动 3% 推近 |
| 跟拍 | 主角在路上走 | `cam(u, d)` 返回主角位置，加 0.3 s 滞后 |
| 平移到下一站 | 同一个世界里换地点 | 下一镜 `at` 放在 1.5 屏以外，`fly: 1.2–2` |
| 推进 / 穿越 | 进到细节里面、下一个尺度 | 下一镜 `at` 的 s 取 0.05–0.15，嵌在细节上 |
| 拉远 / 揭示 | 揭示全貌、给结论 | 下一镜 `at` 的 s 取 3–10，把前面的镜头都包进来 |
| 环绕 | 3D 主体 | backdrop 里相机绕 y 轴走 60–120°，`cubic` |
| 变形接 | 一个形状变成下一个画面的开始 | 上一镜结尾的元素与下一镜开头完全重合，`enter: 'cut'` |
| 叠化 | 换题、时间跳跃 | `enter: 'dissolve'`（同一位置的镜头默认就是叠化） |

节奏：飞行时加速，停下后留出 ≥ 3 s 的稳定时间给字幕和标注。一章里最多一次长距离飞行；全片的镜头运动要有快有慢，不要每次都用同样的 1.2 s。

## 4. 框架约束（换了世界也照样成立）

- HUD、字幕、仪表、lint 在所有世界里都工作。构图检查（`EMPTY / SPARSE / OFF-CENTER / THIN`）按像素算：去掉 HUD 和字幕后的画面，和只有背景的画面相比。满幅的 3D 或 canvas 背景本身不算主体，主体仍要占安全区宽或高的 60%。
- 换主题后 `.card .tag .node` 等组件跟着主题变量变色；自定义纸色、蓝图等主题时，同时改 `--ink --ink2 --card --hud-bg --hud-ink --hud-ink2`，保证字幕可读。
- 所有画面仍是 `t` 的纯函数：canvas 每帧整张重画，three.js 每帧按 t 设姿态再 `renderer.render`。
