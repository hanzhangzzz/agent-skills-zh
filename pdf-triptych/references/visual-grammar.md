# 视觉语法

三张图共用这一套。改任何一条之前，先确认三张图会一起改。

需要的色值、字号、部件画法都在这里，不用去别处找。

## 画布与排版

| 项 | 值 | 理由 |
|---|---|---|
| 画布宽 | `viewBox="0 0 1260 <h>"` | 1260 是能放下中文 9px 小字又不横向滚动的宽度 |
| 页面底色 | `#E7E6E1` | 纸灰，比纯白耐看，也让卡片浮起来 |
| 卡片底色 | `#F0EFEB` | 圆角 24px，无边框无阴影，靠留白分卡 |
| 正文墨色 | `#1F1E1C` | 不用纯黑 |
| 次级文字 | `#6F6E68` | 副标题、箭头标签、说明 |
| 极淡文字 | `#A9A8A2` | 来源行、"不进标准"这类旁注 |
| 网格线 | `#D4D3CC` | 表格内的细分隔线 |
| 字体 | Inter + PingFang SC | 数字和英文用 Inter，中文自动落到苹方 |

字号下限：**中文 9px，英文 8.5px**，绝对下限 8.4px。常见的图表字号下限 6.5 / 5.5px 是给英文和数字定的；中文笔画密，到 6.5px 就糊了。装不下就换行或缩短文案，**不要缩字号**。

另外两条不要动：

- **一律实心**：不透明材质、不发光、不渐变滤镜、无阴影。质感全靠明度对比和形状。
- **卡片四件套**：结论式标题 `h2` + 副标题（图例、单位、范围，` · ` 分隔）+ 图 + 来源行（全大写、加字距）。四件缺一不可，副标题尤其不能省——读者只看这一行就要知道图里每个视觉通道在编码什么。

层级：标题 17px/700，副标题 12px/400，图内主要文字 10–11.5px/600–700，旁注 9–9.5px/400–500。

## 颜色：三类 + 中性

**颜色表达"这个东西属于哪一类"，不表达"它有多重要"。**

```js
const CAT = {
  a: { c:"#2A9D58", t:"#1B7A41", f:"#D5EDDD", name:"<第一类>" },   // 亮绿：线上也认得出
  b: { c:"#C99412", t:"#7A5A08", f:"#F6EACB", name:"<第二类>" },   // 琥珀
  c: { c:"#58402E", t:"#58402E", f:"#E7DED6", name:"<第三类>" },   // 棕
};
```

每类三个值：`c` 描边与线、`t` 文字（比 `c` 深一档，保证小字可读）、`f` 填充（很浅）。

规则：

1. **最多三类。** 超过三类就说明分类维度选错了，回去重新分。
2. **黑灰只给结构**：层的分界虚线、箭头、跨度条、第三维度的横括号、"这是什么图"的说明胶囊。
3. **不要单一强调色。** 数据图表有一个要讲的结论，强调色指向它是对的；概念结构图要讲整体结构，强调色会制造虚假的重点。若确实要突出一支，用加粗或加注，不用独有颜色。
4. **线要比块亮。** `#43593B` 这种低明度绿填成色块能认出是绿，画成 1px 线就和黑色分不清。线色至少要到 `#2A9D58` 这个明度。
5. **图例只画一次**，放在第一张图的末尾（它是全图统一的）；第二张起只写一句"颜色含义与上图相同"。
6. **某张图八成以上是同一个颜色时停一下**：可能是分类维度选错了，也可能是这张图本来就只讲一类东西（例如例子层全是"过程"）。后者可以接受，但要在副标题里说一句，免得读者以为颜色失效了。

## 泳道：虚线不是实体，虚线之间的区域才是

**这是整套坐标系统的核心认知，写错了整张图都会歪。**

竖虚线看起来像一根根"轴"，很容易让人以为它是对齐基准，于是所有东西都去贴它——框贴着画、列头顶着画、连线端点钉在上面。结果就是**全部贴左，右边空一大片**，读起来别扭却说不清哪里不对。

正确的模型是反过来的：

> 虚线是虚拟的分界，本身没有实体。**两条虚线之间的区域（泳道）才是实体**，一切内容都在泳道内居中。

```js
const VW = 1260;                     // 画布宽，最后一个泳道的右界
const X = [70, 200, 335, ...];       // 【泳道的分界线】，不是"列的位置"
const lane = i => { const L = X[i-1], R = (i < X.length ? X[i] : VW);
                    return { L, R, cx: (L+R)/2, w: R-L }; };
const span = (a,b) => { const L = lane(a).L, R = lane(b).R;
                        return { L, R, cx: (L+R)/2, w: R-L }; };
const cx = (i, w) => (Array.isArray(i) ? span(i[0],i[1]) : lane(i)).cx - w/2;
```

**禁止写 `X[i] + 偏移`**。看到这个模式就是错的——它把虚线当成了左基准。一律用 `cx(i, w)` 拿到左上角：

```js
const w = 130;
box(cx(3, w), 200, w, 46, "…");      // 第 3 泳道内居中
```

三类最容易写错的元素，它们同样都要居中：

| 元素 | 错误做法 | 正确做法 |
|---|---|---|
| 泳道头（序号 + 名称） | 贴着虚线右侧起排 | 以 `lane(i).cx` 为中心排。它说的是"这一段区域是什么"，不是"这条虚线是什么" |
| 连接线 | 端点钉在虚线上 | **端点贴的是矩形的边缘**：`M${上一个框右缘},y H${下一个框左缘}`。框居中后端点自然跟着走 |
| 成组的小条 / 刻度 | 从虚线起排 | 整组当成一个宽度，`cx(i, 组宽)` 求出起点再排 |

> **失败模式**：第三次执行（ISO/IEC 25010）时，三张图里 78 个矩形全部贴左，左间距恒为 2–3px，右间距 23–176px。根因不是某几个坐标写错，而是代码通篇 `X[i]+2`、`X[i]+8`、`X[i]+14`——**把虚线当成了左基准**。逐个调 x 改不对：每个泳道宽度不同，手工算偏移改完这个错那个，下次加内容又会错。只有把语义改成泳道、统一走 `cx()`，才是一次性解决。

检查脚本会逐个量：完全落在单个泳道内的矩形，左右间距差超过泳道宽度的 18% 就报。

## 跨泳道与不按列读

### 列归属必须显式声明

共同标尺是这套图的核心契约：**任何元素的横向跨度都在向读者宣称"我属于这些列"**。跨度与真实归属不符，就是在撒谎——和柱状图断轴是同一类错误。

所以横向区块一律走 `place()`，`cols` 参数不给会直接抛错：

| `cols` 取值 | 含义 | 自动处理 |
|---|---|---|
| `[2,5]` | 跨第 2–5 列，按列读 | 什么都不做，让虚线穿过 |
| `5`（数字） | 整块只属于第 5 列，但要更宽才放得下 | 画一条归属线回第 5 列的列头，并加一句说明 |
| `null` | 不按列读：并列的切面、全局性词表、容器框 | 用不透明底色盖住虚线 |

写代码时就得想清楚归属，这比事后检查更早拦住问题。检查脚本会扫所有横跨 ≥1.5 列的矩形，没有 `data-cols` 的报出来。

**失败模式**：第二次执行（ISO/IEC 22989）时，一条四步链横跨全部七列，而它自己的说明写着"这四步都落在第五列那一个阶段里"。视觉和语义直接打架，读者第一眼会把四个框数成四个阶段。同一份产物里另一处却处理对了：三张互不兼容的切面用底色盖住虚线，标题写"它们不是一条线上的三段"。

同一个问题一处解决一处没有——**说明靠文档里的规则拦不住，必须让声明成为书写时绕不过去的动作。** 首次执行（ISO/IEC 25002）其实也有两处未声明：跨度条的起止是手工算的，一个作为容器的虚线框横跨全宽却并不按列读，只是当时没人发现。

## 常用部件

前两个是这套图型特有的，后面几个是通用手法。


### 跨度条（表达"横跨哪几层"）

```js
// 条的起点 = 它从哪一层开始起作用，终点通常到最右
rect({ x: X[from], y, width: X[last]-X[from], height: 9, rx: 4.5, fill: LAD[i] });
```

`LAD = ["#1F1E1C","#4A4944","#6A6963","#8F8E88"]`，同一组条用灰阶区分，不用彩色——彩色留给类别。

### 扇出（表达"数量变多"）

不要从一个点直接散开 300px，线叠线会形成黑楔子。做法：先用一根单线引出去，到接近目标列的位置再散开。

```js
line({ x1: X[2]+225, y1: y, x2: X[3]-150, y2: y, "stroke-width": 1.8 });  // 先引
for (const t of items) link(X[3]-150, y, X[3]-2, t.y, c, 0.9);            // 再散
```

### 文字光晕（压在线上时保持可读）

```js
t.setAttribute("paint-order", "stroke");
t.setAttribute("stroke", PAPER);
t.setAttribute("stroke-width", 4);
```

### 长列表折行（表格里的类型列表）

超过 26 个字符且能按 ` / ` 切分时，折成两行，`y-4` 和 `y+7`。否则会压到下一列。

### 表格

- 表头下一根 1.2px 实线，行间 0.7px 浅线
- 行高 24–32
- 数字列右对齐
- 状态用标签：实心黑底=已有/默认，虚线空心=扩展/提议。**不要用颜色区分状态**，颜色被类别占了

## 交互

默认静态。只在能回答"这一条对应上图哪里"时才加 hover 联动：

```js
document.querySelectorAll("[data-maps]").forEach(el => {
  const ids = el.dataset.maps.split(" ");
  el.onmouseenter = () => all.forEach(n => {
    const on = ids.includes(n.dataset.id);
    n.classList.toggle("hl", on); n.classList.toggle("dim", !on);
  });
  el.onmouseleave = () => all.forEach(n => n.classList.remove("hl","dim"));
});
```

`.hl` 用 `outline` 不用 `border`，避免撑开布局。`.dim` 用 `opacity:.28`。

**不给纯装饰元素加 hover。** 先问一句：这根线背后有没有一条真实记录？没有（示意性的发丝线、只表示"继续变多"的辐条）→ 禁止加交互，给没有内容的元素加 hover 是欺骗。

## 文案

- 标题写**这张图讲什么**，不写图型名。"从一个概念展开到每一条可落地的指标" 好过 "扇出树"。
- 副标题用 ` · ` 分隔，把图例、单位、数据范围、哪些是假设一次说清。
- 来源行全大写加字距，写明：依据哪份文档哪些条款、哪些内容**不来自**这份文档、哪些是演示数据。
- 示意性的元素要标明。"其后的发丝线只示意继续变多，不代表真实数量"这句话必须有。

## 诚实规则

三条硬规则：

- **视觉量要和真实量成正比。** 图里画 9 根短线，原文就必须真的有 9 个条目；示意性的部分要在副标题里写明"只示意继续变多，不代表真实数量"。
- **演示数据用确定性伪随机**，禁用 `Math.random()`。刷新两次必须长一样，否则截图、录屏、回归对比全部失效。可以用 `rnd=(i,k)=>Math.abs(((i*73856093)^(k*19349663))%1000)/1000`。
- **来源行写明边界**：哪些内容不来自这份文档、哪些是假设、哪些是演示数据。结构图最容易出的问题是把"我的理解"画得像"原文就这么说"。

## 动画

默认只用一次淡入：

```css
.fade { animation: fade .9s ease both; }
@keyframes fade { from { opacity: 0 } }
@media (prefers-reduced-motion: reduce) { .fade { animation: none } }
```

不要弹跳，不要逐元素 stagger。滚入视野自动重播那类效果适合数据图表的演示场景；结构图是拿来读和评审的，反复重播只会干扰。

**动画不可优于结构**——一个效果如果需要发明新布局才能安放，它不配存在。
