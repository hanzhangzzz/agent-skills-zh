# 结构探针 · subagent 提问模板

派 opus subagent 通读全文时用这份模板。把 `<PDF路径>`、`<文档名>` 换掉，六个问题一个都不能少。

问题 1 和 2 里的"假设"要先由你自己读完目录和引言后写出来，让 subagent 去证伪——**给一个可证伪的假设，比让它自由发挥得到的结论准确得多**。

---

```
请完整阅读这份 PDF（共约 N 页，用 Read 工具的 pages 参数分批读完，不要只读目录）：
<PDF路径>

这是 <文档名>。图 1–4 是图片，请直接看图。

背景：我要画一张信息图，把这份文档的骨架用一张图讲清楚。我的假设是：
(a) 存在一条"从抽象到具体"的纵向主线：<你读完引言后的假设，例如 A → B → C>；
(b) 另有一些"横向的、适用于全部 X"的内容，例如 <假设的横向内容>。
我不确定这个理解对不对。

请你只依据原文回答，不要用背景知识补全。需要回答：

1. 假设 (a) 是否成立？纵向主线每一层在原文哪里（条款号/图号），层与层之间原文用什么措辞
   连接（请给出英文原句的短引用，每处不超过 25 个英文单词）。有没有被漏掉的层？

2. 假设 (b) 是否成立？逐项判断下面这些内容是"横跨全部层的横向内容"，还是只属于某一层，
   并给条款号和短引用：
   <列出你怀疑是横向内容的条款，逐条列>

3. 文档里每张图的准确内容：每个方框的名字、每条箭头的方向与箭头上的文字、图例的分组各
   包含哪些框。特别确认 <你最不确定的那张图的那个关系>。

4. <如果有结构示意图>该图的准确内容：有哪些框、层级关系、箭头文字、线型是否携带语义。

5. 原文有没有在任何地方使用 <你关心的术语，如 RDF / OWL / 形式化 / 自动推理> 之类的词？
   相关章节是否给出了形式化定义？

6. 基于以上，请给出你认为最忠实于原文的"信息架构"建议：哪些内容构成纵向主线（按顺序），
   哪些是横跨主线的横向内容，它们各自横跨哪几层，有没有独立的第三维度。用一个简洁的
   ASCII 草图表示。

7. 列出任何你发现的、容易被误读的点（例如某条规则原文用的是 should 还是 shall、某个限定
   词、某个说法其实只针对某一类对象而不是全部）。

输出要求：中文，结构化，每个结论后面带条款号或图号，关键处带英文短引用。区分"原文明说的"
和"你的推断"。不要修改任何文件。
```

---

## 怎么用返回结果

subagent 返回后做三件事：

1. **把它纠正你的地方单独记下来。** 这些是图注和"易误读"区的素材。
2. **ASCII 草图直接当布局草稿。** 主线的层数决定图一有几列，横向内容的跨度决定长短条从哪一列起。
3. **易误读点至少挑 2–4 条放进图里。** 这是"真读过原文"最有力的证据，也是这张图比网上随便一张架构图可信的地方。

## 追问的时机

只在以下情况追问，其余情况自己判断：

- 返回的某条结论没有给条款号或引用
- 两个结论互相矛盾
- 图的描述与你 Read 看到的不一致（以你看到的为准，但要问清它为什么那么说）
